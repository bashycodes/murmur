# Air-gapped end-to-end check (2026-11-01)

Ticket "1.0.0 · 8". Script: `tools/e2e/airgap/run.sh` (README next to it);
client: `crates/murmur-remote/examples/airgap_e2e.rs`. Owner guide:
`docs/air-gapped.md`.

## Setup

* murmur-server 0.12.0 built from `feat/airgap-guide` (off integration
  `f0c2122`), release, default features `whisper,tls`; the client example
  is a debug build of murmur-remote with `library` (the code Windows uses
  directly and Android through murmur-ffi).
* Server on `127.0.0.1:17399`, temp state dir, temp library, `rescan_s = 2`.
* Speech engine: **real** whisper.cpp with `ggml-tiny.en.bin` (read in place,
  read only). Library: copies of two **real** model files, tagged as custom
  models: `whisper-tiny-en` (`kind = "stt"`, `engine = "whisper"`,
  `ggml-tiny.en.bin`, 77.7 MB) and `whisper-tiny-lid` (`kind = "lid"`,
  `ggml-tiny.bin`, 77.7 MB), plus an untagged folder that must be skipped.
* Clip: `jfk.wav`, the whisper.cpp sample (public-domain JFK speech, 11 s).

## Network isolation

`unshare -rn` (user + network namespace) is **not available** on this box:
Ubuntu's `kernel.apparmor_restrict_unprivileged_userns = 1` makes
`unshare` fail writing `uid_map`. The script tries it and, when it works,
runs the server and the client in a loopback-only namespace. Here it fell
back to loopback only, with an audit: both processes run under
`strace -f -s 0 -e trace=connect,sendto,sendmsg`, and the check fails on
any inet destination that is not `127.0.0.1` / `::1`. The audit itself was
checked by tracing `curl http://192.0.2.1/`, which it reports. Result: 13
client connects, all `127.0.0.1`; the server made none (it only accepts).

  `ServerCatalogTest`), resume after a cut (in `murmur-remote/tests/library.rs`).
